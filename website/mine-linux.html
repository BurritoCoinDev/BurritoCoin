🐧 Mining on Linux

About 20–30 minutes, most of it compiling. The commands assume Ubuntu/Debian, with Fedora notes inline; adapt the package names for other distros. Mining uses the node's own built-in miner — there's nothing else to install.

Step 1 of 5

Install BurritoCoin Core

1

Install build dependencies

Ubuntu / Debian:

sudo apt update
sudo apt install -y build-essential libtool autotools-dev automake \
  pkg-config bsdmainutils python3 libssl-dev libevent-dev libboost-all-dev \
  libsqlite3-dev libdb-dev libdb++-dev libminiupnpc-dev libzmq3-dev \
  libfmt-dev git curl

Fedora:

sudo dnf install -y gcc-c++ make autoconf automake libtool pkgconf-pkg-config \
  openssl-devel libevent-devel boost-devel sqlite-devel libdb-devel \
  libdb-cxx-devel miniupnpc-devel zeromq-devel fmt-devel git curl python3
2

Clone and build

git clone https://github.com/BurritoCoinDev/BurritoCoin.git
cd BurritoCoin
./autogen.sh
./configure --without-gui --disable-tests --disable-bench \
  --with-incompatible-bdb --with-boost-system=no
make -j$(nproc)
sudo make install

The build takes 10–30 minutes depending on your machine. The binaries burritocoind and burritocoin-cli end up in /usr/local/bin/.

--with-boost-system=no is needed on newer distros such as Ubuntu 26.04 and Fedora 44, whose Boost no longer ships a separate Boost.System library. It's harmless on older ones.

Want the node as a system service? After building, sudo ./contrib/vps/setup.sh mainnet installs it as a systemd service running under its own user. You don't need that just to mine. See doc/build-unix.md for more build options.
Step 2 of 5

Configure and Start the Node

1

Create the config file

mkdir -p ~/.burritocoin
printf 'daemon=1\nserver=1\n' > ~/.burritocoin/burritocoin.conf

That's all it needs: run the node in the background and accept commands from burritocoin-cli. There's no RPC password to set — burritocoin-cli signs in with a cookie file the node writes to ~/.burritocoin, readable only by you, and the node only listens for commands on this machine.

2

Start the node

burritocoind

You'll see "BurritoCoin Core starting" and get your prompt back — it's running in the background. Give it a few seconds before the next command; right after starting, burritocoin-cli may say it can't connect yet.

Step 3 of 5

Set Up Your Wallet

1

Create a wallet

burritocoin-cli -named createwallet wallet_name=mining load_on_startup=true

load_on_startup=true makes the node open this wallet every time it starts. Without it the wallet silently stays closed after a restart, and your balance looks like it vanished.

2

Encrypt it

burritocoin-cli encryptwallet "YOUR_LONG_PASSPHRASE"

The node keeps running. Mining doesn't need the wallet unlocked; you'll only need the passphrase to spend:

burritocoin-cli walletpassphrase "YOUR_LONG_PASSPHRASE" 60

(60 = seconds before it locks again.)

Write the passphrase down somewhere safe. Nobody can reset it. Without it, every BRTO in this wallet is gone for good — and the backup below is encrypted with it too.
3

Back it up

burritocoin-cli backupwallet ~/wallet-backup.dat

Copy wallet-backup.dat off this machine. Back up after encrypting: encrypting generates a new seed, so a backup taken before it won't cover the addresses you use from now on.

Step 4 of 5

Check You're Synced

1

Compare your height with the network's

burritocoin-cli getconnectioncount
burritocoin-cli getblockcount

You want at least 1 connection, and a block count that matches the latest block on explorer.burritoco.in. The chain is small, so this takes a minute or two after starting.

Ignore "initialblockdownload" in getblockchaininfo for this. If nobody has mined for over a day, it stays true even on a fully synced node, because the node treats any chain whose newest block is more than a day old as still catching up. The matching height is what counts, and the first new block anyone mines clears the flag.

Don't mine until the heights match. A node that hasn't caught up would mine on an old part of the chain, and the network throws those blocks away.
Step 5 of 5

Start Mining

1

Run the miner

ADDR=$(burritocoin-cli getnewaddress)
while true; do
  burritocoin-cli -rpcclienttimeout=0 generatetoaddress 1 "$ADDR"
done

This is the node's built-in miner. Each pass tries a million hashes, then prints what it found: [] means no block that time, which is normal. A long hex hash in brackets means you found a block. Stop with Ctrl+C.

One loop keeps one CPU core busy. To use more cores, start more loops — each in its own terminal, each with its own ADDR so they don't repeat each other's work — and add rpcthreads=16 to ~/.burritocoin/burritocoin.conf (then restart the node), so the loops don't queue up behind one another.

2

Keep it running after you log out

sudo apt install -y tmux     # Fedora: sudo dnf install -y tmux
tmux new -s mining
# start the loop above, then detach with Ctrl+B, then D
# come back later: tmux attach -t mining
3

Check your rewards

burritocoin-cli getbalances

Each block pays 10 BRTO. New coins first show up as "immature" and move to "trusted" (spendable) once 100 more blocks have been mined on top: about four hours at the network's 2.5-minute target, longer while few people are mining. getbalance only counts spendable coins, so it stays at 0 until then.

Why not cpuminer? Stock miners like cpuminer-opt can't mine BurritoCoin. The node only hands out work to miners that declare support for MWEB, BurritoCoin's privacy extension, and they don't — so it refuses every request. (Once MWEB activates, blocks must also carry MWEB data, which they can't build.) The built-in miner builds blocks itself, so neither problem applies.
Troubleshooting

Common Problems

"Could not connect to the server 127.0.0.1:9226"

The node is still starting, or isn't running. Wait a few seconds and try again; if it persists, start it with burritocoind.

The block count stays at 0

Your node can't get the chain. Check burritocoin-cli getconnectioncount: at 0, something is blocking outgoing connections to port 9227. With a connection and still 0 after 15 minutes, don't mine — open an issue on GitHub.

"No wallet is loaded" or "Requested wallet does not exist"

Open it with burritocoin-cli loadwallet mining. If you created it without load_on_startup=true, do this after every restart, or re-run loadwallet with -named ... load_on_startup=true.

"Cannot obtain a lock on data directory"

The node is already running. There's nothing to start.

The build fails with a Boost error

Make sure you passed --with-boost-system=no to ./configure, and that your checkout is current (git pull) — older checkouts don't build against the Boost that ships with current distros.

How do I stop mining?

Ctrl+C in the loop's terminal. Stop the node with burritocoin-cli stop.

Can I mine on a Raspberry Pi?

On a 64-bit OS, yes: these steps build fine on 64-bit ARM (the network's own seed node is an ARM server). Expect a modest hash rate, but a Pi uses very little power, so it makes a reasonable always-on miner while the network is small.
