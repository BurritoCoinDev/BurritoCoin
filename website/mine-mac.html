🍎 Mining on macOS

About 30 minutes on Apple Silicon (M1–M4), most of it compiling. You'll use Terminal and Homebrew. Intel Macs work too, but Homebrew no longer ships ready-built packages for Intel, so installing the dependencies can take an hour or more there.

Step 1 of 5

Install BurritoCoin Core

1

Open Terminal

Press ⌘ + Space, type "Terminal", press Enter.

2

Install Homebrew (if you don't already have it)

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

When it finishes, look for Next steps at the end of its output and run the commands it lists. On Apple Silicon those are:

echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"

Check with brew --version. Skip this step if you already have Homebrew.

3

Install build dependencies

brew install automake libtool boost pkg-config libevent sqlite miniupnpc zeromq fmt berkeley-db@5

The wallet uses Berkeley DB 5.3, which Homebrew ships ready-built as berkeley-db@5.

4

Clone and build

Homebrew installs into /opt/homebrew on Apple Silicon and /usr/local on Intel, and the configure script doesn't look in either by default. BREW_PREFIX points it at the right one:

git clone https://github.com/BurritoCoinDev/BurritoCoin.git
cd BurritoCoin
./autogen.sh
export BREW_PREFIX="$(brew --prefix)"
./configure --without-gui --disable-tests --disable-bench \
  --with-boost="$BREW_PREFIX/opt/boost" --with-boost-system=no \
  BDB_LIBS="-L$BREW_PREFIX/opt/berkeley-db@5/lib -ldb_cxx-5.3" \
  BDB_CFLAGS="-I$BREW_PREFIX/opt/berkeley-db@5/include" \
  CPPFLAGS="-I$BREW_PREFIX/include" \
  LDFLAGS="-L$BREW_PREFIX/lib"
make -j$(sysctl -n hw.ncpu)
sudo make install

This takes 10–20 minutes and installs burritocoind and burritocoin-cli into /usr/local/bin/. --with-boost-system=no is needed because Homebrew's Boost no longer ships a separate Boost.System library.

More background is in doc/build-osx.md. It's older than this page: where the two disagree, follow this page.
Step 2 of 5

Configure and Start the Node

1

Create the config file

mkdir -p ~/Library/Application\ Support/BurritoCoin
printf 'daemon=1\nserver=1\n' > ~/Library/Application\ Support/BurritoCoin/burritocoin.conf

That's all it needs: run the node in the background and accept commands from burritocoin-cli. There's no RPC password to set — burritocoin-cli signs in with a cookie file the node writes to that folder, readable only by you, and the node only listens for commands on this Mac.

2

Start the node

burritocoind

You'll see "BurritoCoin Core starting" and get your prompt back — it's running in the background. Give it a few seconds before the next command; right after starting, burritocoin-cli may say it can't connect yet.

Step 3 of 5

Set Up Your Wallet

1

Create a wallet

burritocoin-cli -named createwallet wallet_name=mining load_on_startup=true

load_on_startup=true makes the node open this wallet every time it starts. Without it the wallet silently stays closed after a restart, and your balance looks like it vanished.

2

Encrypt it

burritocoin-cli encryptwallet "YOUR_LONG_PASSPHRASE"

The node keeps running. Mining doesn't need the wallet unlocked; you'll only need the passphrase to spend:

burritocoin-cli walletpassphrase "YOUR_LONG_PASSPHRASE" 60

(60 = seconds before it locks again.)

Write the passphrase down somewhere safe. Nobody can reset it. Without it, every BRTO in this wallet is gone for good — and the backup below is encrypted with it too.
3

Back it up

burritocoin-cli backupwallet ~/wallet-backup.dat

Copy wallet-backup.dat off this Mac. Back up after encrypting: encrypting generates a new seed, so a backup taken before it won't cover the addresses you use from now on.

Step 4 of 5

Check You're Synced

1

Compare your height with the network's

burritocoin-cli getconnectioncount
burritocoin-cli getblockcount

You want at least 1 connection, and a block count that matches the latest block on explorer.burritoco.in. The chain is small, so this takes a minute or two after starting.

Ignore "initialblockdownload" in getblockchaininfo for this. If nobody has mined for over a day, it stays true even on a fully synced node, because the node treats any chain whose newest block is more than a day old as still catching up. The matching height is what counts, and the first new block anyone mines clears the flag.

Don't mine until the heights match. A node that hasn't caught up would mine on an old part of the chain, and the network throws those blocks away.
Step 5 of 5

Start Mining

1

Run the miner

ADDR=$(burritocoin-cli getnewaddress)
caffeinate -i bash -c "while true; do
  burritocoin-cli -rpcclienttimeout=0 generatetoaddress 1 $ADDR
done"

This is the node's built-in miner. caffeinate -i keeps your Mac awake while it runs — a sleeping Mac doesn't mine. Each pass tries a million hashes, then prints what it found: [] means no block that time, which is normal. A long hex hash in brackets means you found a block. Stop with Ctrl+C.

One loop keeps one CPU core busy. To use more cores, open more Terminal windows and start another loop in each — each with its own ADDR, so they don't repeat each other's work — and add rpcthreads=16 to burritocoin.conf (then restart the node), so the loops don't queue up behind one another.

2

Check your rewards

burritocoin-cli getbalances

Each block pays 10 BRTO. New coins first show up as "immature" and move to "trusted" (spendable) once 100 more blocks have been mined on top: about four hours at the network's 2.5-minute target, longer while few people are mining. getbalance only counts spendable coins, so it stays at 0 until then.

Why not cpuminer? Stock miners like cpuminer-opt can't mine BurritoCoin. The node only hands out work to miners that declare support for MWEB, BurritoCoin's privacy extension, and they don't — so it refuses every request. (Once MWEB activates, blocks must also carry MWEB data, which they can't build.) The built-in miner builds blocks itself, so neither problem applies.
Troubleshooting

Common Problems

"zsh: command not found: brew"

Homebrew isn't on your PATH yet — run the two Next steps commands from Step 1, or open a new Terminal window.

"command not found: burritocoind"

sudo make install puts it in /usr/local/bin on both Apple Silicon and Intel. Try /usr/local/bin/burritocoind, or run it from the build folder: ~/BurritoCoin/src/burritocoind.

configure: "Could not find a version of the Boost::System library"

Add --with-boost-system=no to the ./configure line, as shown in Step 1.

The build fails in wallet/bdb.cpp with "copy_option"

Your checkout predates the fix for newer Boost. Run git pull in the BurritoCoin folder and build again.

"Could not connect to the server 127.0.0.1:9226"

The node is still starting, or isn't running. Wait a few seconds and try again; if it persists, start it with burritocoind.

The block count stays at 0

Your node can't get the chain. Check burritocoin-cli getconnectioncount: at 0, something is blocking outgoing connections to port 9227. With a connection and still 0 after 15 minutes, don't mine — open an issue on GitHub.

"No wallet is loaded"

Open it with burritocoin-cli loadwallet mining.

How do I stop mining?

Ctrl+C in the loop's window. Stop the node with burritocoin-cli stop.
